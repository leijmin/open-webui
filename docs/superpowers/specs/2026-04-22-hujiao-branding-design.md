# 胡椒文旅品牌化与老板视角简化设计

## 背景

当前站点基于 `Open WebUI v0.8.10` 部署，已经能够正常运行，但默认界面仍保留了明显的开源产品品牌、社区入口、英文文案和偏技术化的信息架构。对于“河南省胡椒文化传媒有限公司”的内部展示场景，这些内容会增加理解成本，也会削弱企业产品感。

本次改造目标是在保留现有稳定聊天能力的前提下，将站点调整为更适合公司内部展示和日常使用的“胡椒文旅智能助手”。

## 适用范围与假设

- 使用场景为公司内部展示与内部使用，不对外公开售卖。
- 主品牌统一使用 `胡椒文旅`。
- logo 以用户提供的品牌图为准：
  - 源图：`/Users/leijianmin/Documents/Uniapp 开发方案与报价梳理/微信图片_20260408223154_97_1287.jpg`
- 本次以“优化现有产品外层体验”为主，不重写聊天核心能力，不改造底层模型调用链路。
- 部署目标服务器保持不变：`root@118.31.70.82`
- 线上运行目录保持不变：`/www/wwwroot/hujiao_icloverai_cn`
- 线上服务保持不变：`open-webui.service`

## 目标

1. 完整替换前台可见品牌为 `胡椒文旅`
2. 让普通使用者尽量只看到中文界面
3. 去掉 GitHub、Discord、X、作者、社区、开源宣传等不适合企业老板视角的信息
4. 收敛明显偏技术、偏开发者的入口与说明
5. 保留后台管理和基础设置能力，但降低默认曝光度
6. 提供一份可重复执行的一键发布脚本，便于后续自行部署

## 非目标

- 不改写后端模型接入架构
- 不新增复杂业务模块或独立首页系统
- 不重构数据库结构
- 不对所有隐藏页面做彻底删除，只优先减少主流程中的暴露
- 不处理与品牌授权之外的法律事务；授权前提以用户确认的内部使用场景为假设

## 方案选择

本次采用“品牌化 + 老板视角简化”方案。

原因：

- 比单纯替换 logo 和名称更贴近真实使用目标
- 比深度门户化改造更稳，升级成本更低
- 能最大程度复用 Open WebUI 现有稳定能力，减少部署风险

## 设计方案

### 1. 品牌与视觉

#### 品牌命名

- 全站主品牌显示统一为 `胡椒文旅`
- 不再在前台叠加显示 `Open WebUI`

#### logo 体系

- 基于提供的品牌图导出两类素材：
  - 横版品牌图：用于登录页、启动页、必要的品牌展示位
  - 圆形图标：用于 favicon、侧边栏头像、通知图标
- 生成并替换的静态资源包括但不限于：
  - `favicon.png`
  - `favicon-dark.png`
  - `favicon.ico`
  - `favicon.svg`
  - `favicon-96x96.png`
  - `apple-touch-icon.png`
  - `logo.png`
  - `splash.png`
  - `splash-dark.png`

#### 视觉方向

- 主色调向 logo 的绿色系靠拢
- 登录页和启动页从“开源工具欢迎页”调整为“企业内部智能助手入口”
- 避免出现社区型徽章、社交媒体按钮和开源产品式宣传区块

### 2. 中文优先与文案收敛

#### 默认语言

- 默认语言改为 `zh-CN`
- 首次进入时优先使用后端默认中文，不依赖浏览器语言猜测

#### 文案策略

- 登录页、引导页、空状态、设置页优先改为简明中文
- 删除或替换明显不符合企业场景的文案，例如：
  - “Explore the cosmos”
  - “See what's new”
  - “Help us translate Open WebUI”
  - “Discover how to use Open WebUI and seek support from the community.”
- 文案风格目标：
  - 少术语
  - 少宣传
  - 直接告诉用户下一步怎么做

### 3. 信息架构简化

#### 对普通用户保留的主路径

- 登录
- 新建对话
- 查看历史对话
- 打开设置
- 退出登录

#### 降低曝光或隐藏的入口

- `Playground`
- `Workspace`
- 社区分享与社区榜单相关入口
- 文档与 Releases
- GitHub / Discord / X 跳转
- 作者、版权宣传、Twemoji 说明等前台展示区块
- 更新检查、更新日志入口

#### 管理能力

- 管理员保留基础后台能力
- 管理入口可以继续存在，但不在普通使用路径中强调

### 4. 页面级改造范围

#### 登录页

- 替换为胡椒文旅 logo
- 浏览器标题显示 `胡椒文旅`
- 引导文案改为企业内部智能助手风格
- 删除英文 onboarding 轮播语句
- 将“本地部署/外部连接”等技术说明替换为更通俗的内部使用说明

#### 启动页与浏览器标识

- 替换页面 title、favicon、manifest、opensearch 文案
- 替换启动页 logo 和配色
- 浏览器通知标题中的 `Open WebUI` 改为 `胡椒文旅`

#### 侧边栏与用户菜单

- 使用胡椒文旅图标
- 去掉不必要的技术入口与帮助链接
- 保留核心操作与设置入口

#### 设置页

- About / General 页面移除 GitHub、Discord、X、作者、版本宣传、开源社区相关说明
- 关闭“检查更新”“查看更新内容”等非必要信息入口
- 移除“帮助我们翻译 Open WebUI”等开源协作信息
- 保留与当前内部使用场景相关的基础设置项

### 5. 技术实现边界

#### 前端

- 直接修改 Svelte 前端可见品牌与导航结构
- 优先通过隐藏、裁剪和文案替换完成体验简化
- 不大规模重构现有路由结构

#### 后端

- 调整默认站点名称、默认语言、manifest/opensearch 输出内容
- 优先使用已有配置能力；必要时补充定制逻辑
- 不破坏当前 Python 原生部署方式

#### 部署兼容性

- 保留线上现有 `venv`
- 保留为旧版 SQLite 兼容而添加的 `sitecustomize.py`
- 新部署流程不能覆盖或移除这部分兼容补丁

## 发布脚本设计

新增或重写 `deploy-hujiao-rsync.sh`，目标是让后续发布流程尽量变成单命令执行。

### 脚本职责

1. 校验本地仓库路径和目标服务器配置
2. 构建前端静态资源
3. 通过 `rsync` 将项目同步到服务器目标目录
4. 避免覆盖以下线上已有关键文件：
   - `venv/`
   - 自定义 `sitecustomize.py`
   - 运行期数据目录
5. 在服务器上按需安装 Python 依赖
6. 重启 `open-webui.service`
7. 执行健康检查并输出结果

### 脚本使用体验

- 支持在本地仓库根目录直接执行
- 支持显式配置服务器地址、目标目录和服务名
- 出错时立即退出并给出明确提示
- 成功后输出站点访问地址和服务状态摘要

## 验收标准

### 品牌

- 浏览器标题、登录页、侧边栏、通知标题、favicon、启动页均显示 `胡椒文旅`
- 默认界面中不再出现 `Open WebUI` 文字品牌

### 中文

- 首次打开站点默认进入中文界面
- 主流程中不出现明显英文引导语和社区宣传语

### 简化

- 普通用户视角下看不到 GitHub、Discord、X、作者、社区分享、更新宣传等内容
- 用户菜单和设置页更接近企业内部工具而非开源产品

### 部署

- 能通过一条脚本命令完成同步、重启和健康检查
- 不破坏现有线上 Python 原生部署和 SQLite 兼容补丁

## 风险与处理

### 品牌替换覆盖不完整

风险：站点中仍可能有零散 `Open WebUI` 文案残留。  
处理：以全文搜索方式覆盖主流程文案，并在实现完成后做一次全局回查。

### 静态 logo 素材适配不足

风险：用户提供的是一张 JPG 宣传图，不一定天然适合 favicon 与透明背景场景。  
处理：先从原图提取可用版本，必要时生成裁切版与透明背景版，以保证小尺寸清晰度。

### 隐藏入口过多影响管理员使用

风险：如果全部彻底删除，后续维护可能不便。  
处理：优先做“降低曝光”而不是“删掉底层能力”，保证管理员仍可进入必要页面。

### 发布脚本误覆盖线上关键文件

风险：`rsync` 配置不当可能冲掉线上运行环境或兼容补丁。  
处理：在脚本中明确排除清单，并在上线前先打印同步策略。

## 实施顺序

1. 生成并接入胡椒文旅品牌静态素材
2. 改品牌名称、标题、通知和启动页
3. 改登录页、引导页与核心中文文案
4. 去除 GitHub / 社区 / 更新宣传入口
5. 简化用户菜单、设置页和侧边栏暴露项
6. 补充默认中文与后端品牌输出
7. 编写并验证 `deploy-hujiao-rsync.sh`
8. 部署到服务器并做上线验证
